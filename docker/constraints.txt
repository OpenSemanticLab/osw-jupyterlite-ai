# The stack this flavour is pinned to, and why it is not simply "latest".
#
# The deciding constraint is Python, not JupyterLite. osw, oold and opensemantic all build
# their models on `pydantic.v1`, and pydantic says plainly, at import time, that "Core
# Pydantic V1 functionality isn't compatible with Python 3.14 or greater". Measured
# against pydantic 2.12.5, the version every current Pyodide build ships:
#
#   python 3.14 + pydantic 2.12.5 -> ConfigError: unable to infer type for attribute "text"
#   python 3.13 + pydantic 2.12.5 -> imports fine
#
# (pydantic fixed its v1 shim for 3.14 by 2.14, but pydantic-core is compiled, so the
# kernel gets whatever Pyodide ships and micropip cannot replace it.)
#
# So the kernel has to be a Python 3.13 Pyodide:
#
#   jupyterlite-pyodide-kernel 0.7.2 -> pyodide 0.29.3 -> python 3.13.2, pydantic 2.12.5
#   jupyterlite-pyodide-kernel 0.8.x -> pyodide 314.x  -> python 3.14, which breaks osw
#
# 0.7.x pulls jupyterlite-core 0.7.x, which ships JupyterLab 4.5 - still within
# jupyterlite-ai 0.20.1's requirement of >=4.5.0. The whole set is consistent; revisit it
# when opensemantic/oold move off pydantic.v1, or when Pyodide ships pydantic >=2.14.
jupyterlite-core>=0.7.1,<0.8
jupyterlite-pyodide-kernel==0.7.2

# Pinned exactly by the base project too: jupyterlite-ai is young and the plugin ids the
# settings override depends on move between releases.
jupyterlite-ai==0.20.1
